# Reference

Reference pages describe facts that readers look up repeatedly. They should be precise, predictable, and lighter on narrative than guides.

## Planned sections

### Configuration reference

List every supported field, accepted value, default, and restart requirement.

### API reference

Document endpoints, request and response shapes, authentication, and errors.

### Events

Describe event names, payload types, publishers, subscribers, and ordering guarantees.

### Glossary

Define project-specific terms and link each term to its primary guide.

::: tip Separate guides from reference
A guide answers “how do I complete this task?” A reference answers “what exactly does this field or interface mean?”
:::
