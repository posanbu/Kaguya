# 记忆配置

Kaguya 的 Memory 目录包含五个模块：`memory.identity`、`memory.expression`、`memory.raw`、`memory.native` 和 `memory.mem0`。

## 手动管理记忆图

在工作台侧栏打开 **记忆**。页面直接读取 PostgreSQL 中的节点与有向关系。可按正文、标签和出现时间筛选；多个标签按同时匹配处理。

选择 **新增记忆**，在浮层面板中填写出现时间、标签和文本或 Markdown 正文后保存。时间按浏览器本地时区输入。其他 metadata 可以在面板中以 JSON 字典填写。点击图中的节点或节点列表可检视完整正文、metadata 和 ID；选择 **编辑** 会在同样的浮层中载入原内容。未保存的修改在关闭面板时会提示确认。

选择 **新增连结**，在浮层中指定起点、终点和关系类型；也可以选择图工具栏的 **连线**，依次点选起点和终点，再在浮层中填写关系。相同方向的两个节点可以有多种关系类型，反向关系单独保存。点击连线可查看关系 metadata 或删除这条关系。删除节点前会确认，同时删除其全部入边和出边。

画布采用 Obsidian 风格的小圆点和细线，支持力导向布局、拖拽、缩放和适应全部节点。悬停或选中节点会突出相邻关系并显示方向；标签可以通过图工具栏切换。节点面板的 **查看一跳关联** 显示该节点及直接相连的节点。每批最多显示 100 个节点和 1000 条内部关系，截取时页面会提示；可缩小筛选范围或查看下一批。普通筛选视图只显示当前节点之间的关系。

图上方的 **节点颜色** 提供三种信息维度，并显示分组名称和当前节点数。默认按 **首个标签** 分组，同名标签在不同筛选下使用相同颜色；无标签节点单独归组，标签多于八组时其余归入“其他标签”。**出现时间** 按 24 小时、7 天和 30 天分段，未来时间单独标记。**当前图关系条数** 区分 0 条、1–2 条、3–5 条和 6 条及以上；多种类型的边分别计数，自环计一次。选中节点时保留分组填色，并用外圈标记当前选择。

## 原始事件记忆与开关

运行时始终把入选的原始事件及其证据写入 Memory。Light 与 Heavy 在同一轮读取同一份冻结的“全面背景”和“当前 scope 上下文”；当前块标出尚未观察的入站消息。背景包含最近的各会话事件，因此模型可能看到其他会话的事实；最终发送仍受目标授权检查。

“概览”的 **长期记忆索引** 开关控制额外的入站原文文档、稀疏索引与长期召回能力。开关默认关闭，保存后重启生效。关闭不会删除已有文档或始终写入的原始事件，也不影响上述两块近期背景。开启时会为既有文档补建稀疏索引。

`memory.identity` 负责会话和人物身份，`memory.expression` 负责表达习惯。它们仍按各自模块配置运行。

## 尚未完成的模块

`memory.native` 计划统一自研的联想与索引，见 [跟踪 Issue #265](https://github.com/posanbu/Kaguya/issues/265)。`memory.mem0` 计划承载 Mem0 认知记忆，见 [跟踪 Issue #266](https://github.com/posanbu/Kaguya/issues/266)。模块目录显示“未完成”和 Issue 链接；这两个模块没有实例、启用开关、检索、订阅或后台任务。

当前聊天的两块事件背景来自原始 Memory；独立的可选记忆与人物身份仍按原有流程装配。`memory.native` 和 `memory.mem0` 尚未提供额外认知召回。
