# 记忆配置

Memory 让已保存的历史消息参与后续回复。默认关闭；初次使用先确认模型和聊天正常，再决定是否开启。

## 开启基础记忆

在配置页启用 **Memory**，保存并应用当前配置。

**`memory.enabled`** — 总开关，默认 `false`。开启后启用原始消息写回和内置文本检索，不需要额外的 embedding 或 Mem0 服务。

关闭后不再读取、写入或召回实际 Memory，已有数据不会因此删除。网页对话记录与 Memory 是不同用途的功能，关闭记忆不等于删除聊天记录。

历史聊天消息会在对应的会话范围内按需取用；通过下方“记忆录入”主动提供的内容则进入全局 Memory。两者都不保证每次提问召回所有相关内容。

## 可选：向量检索

需要按语义检索时，可以在 Profile JSON 的 `memory.embedding` 中配置模型服务。网页可编辑 Memory 和事件 / Wiki 开关；embedding 等高级字段请先停服、备份，再修改文件并重启。

**`providerId`** — 本地使用的供应商标识。

**`modelId`** — 服务实际提供的 embedding 模型 ID。

**`revision`** — 这套索引的版本标识。更换模型或需要重新处理历史时使用新值。

**`dimensions`** — 模型输出维度，范围 `1–16000`，必须与实际输出一致。

**`baseUrl` / `apiKey`** — embedding 服务地址与密钥。

向量功能还需要安装了 pgvector 的 PostgreSQL 17。默认托管镜像不含此扩展；需准备外部数据库，按[运行参数](./runtime)接入。向量不可用时仍可使用基础文本检索。

## 可选：认知服务

`memory.cognition` 可连接独立部署的 Mem0 REST 服务，用于从有界的历史消息窗口提取事实。

**`provider`** — 固定为 `mem0-rest`。

**`revision`** — 认知配置的版本标识。

**`baseUrl` / `apiKey`** — Mem0 服务地址与凭据。Kaguya 不会自动部署或启动 Mem0，它的模型和数据库也要另外配置。

启用认知并不等于拥有无限历史的人物画像。身份未解析的消息和 Web 临时身份消息不触发长期认知，基础消息记忆仍独立工作。可复制的配置片段和服务契约见[Memory 开发参考](../developers/memory#配置和启用)。

## 可选：事件与 Wiki 原型

**`memory.knowledgeEnabled`** — 默认不启用。与 `memory.enabled: true` 一起使用时，开启事件、实体与 Wiki 的首版原型。关闭后保留已有数据。

此项仍需要效果与成本验证，普通聊天无需开启。实现边界见[事件与 Wiki 说明](../developers/memory#adr-事件、实体与-wiki-的可回退原型)。

## 从网页主动录入记忆

在配置页同时勾选 **启用 Memory** 和 **启用事件 / Wiki 记忆与主动录入**，保存并应用配置，然后打开主导航的 **记忆录入**。

选择信息来源后，输入自然语言，例如“小夏喜欢天文，和小林是从小认识的朋友”。这里录入的内容统一保存到全局 Memory，网页聊天、平台群聊和私聊都可以按需召回，无需选择适用范围。信息来源区分用户陈述和角色设定；人工输入不会自动成为已核实的事实。

点击 **发送给 Agent** 后，系统会显示处理中、需要补充、已入库、部分完成或失败。出现同名人物时，选择对应身份并在输入区补充说明。同一次录入会保留上下文；点击 **新录入** 开始另一组内容。当前标签页中的 **录入记录** 可切回之前的会话；服务端记录持久保存在数据库中。

结果会逐项显示新增、关联已有、修订和未处理内容。**查看来源与记录** 可核对原文来源及修订关系。重复提交复用同一请求；网络中断后点击 **重新提交** 可确认原请求的状态。处理失败会保留原文并显示原因，使用 **重试这一条** 继续；不兼容的旧版本任务需要新建录入重新提交。

**已保存的记忆** 列表从服务器读取，可跨录入会话查找人物或内容。点击一条记录旁的铅笔，会把该记录带到输入区；再告诉 Agent 怎么修改，例如“把喜好改成绘画”。也可以直接发送包含人物、原内容和新内容的更正指令。修改完成后，新内容替代原记录，旧版本和来源保留用于追溯。普通新值与旧值冲突时会先澄清；明确为可并存的补充时会保留旧值。

点击记录旁的垃圾桶可删除该条记忆，删除后不再参与后续召回。误删时点击该条记录的 **撤销** 可恢复。删除采用可恢复的撤回记录，不会清除历史来源和操作记录；仍在处理的旧修改指令不能恢复已删除内容。

当前每次录入最多 20 条输入、合计 24000 字符；每轮最多整理 16 个主体和 32 条断言，超出或无法确定的内容会显示为未处理。

录入内容保存在 Memory 数据库，通过有来源的原文片段按需召回；不会改写人设模板或系统指令。默认按有界关键词查找，不能保证每次提问都召回所有相关记忆。AI 整理规则使用当前配置的 heavy 模型；需要修改通用规则时，可在 **检查 → 事件与 Wiki 记忆 → 提示词模板** 编辑“主动记忆整理规则”。
