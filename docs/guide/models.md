# 模型配置

打开 Web UI 的配置页，选择要编辑的 Profile。首次使用只需填写服务地址、密钥和两个模型名称，然后保存并[应用当前配置](./configuration#保存后怎样生效)。

## 必填的连接信息

**Base URL** — 模型供应商提供的兼容 OpenAI API 地址，通常包含 `/v1`。填写 API 入口，不是供应商的网页聊天地址。

**API Key** — 该服务的访问密钥。密钥保存在本机配置文件中，不要放入截图或公开日志。

**轻量模型（Light Model）** — 轻量任务使用的模型名称，默认用于判断这一轮如何参与对话。优先使用响应较快且支持所需结构化输出的模型。

**重量模型（Heavy Model）** — 默认用于编写回复正文的模型名称。只有一个模型时，Light 和 Heavy 填同一个名称即可。

模型名称必须是供应商实际提供的 ID。Light 和 Heavy 是任务分工，不会自动下载模型，也不会在其中一个失败时自动切换另一个。

## 超时与思考选项

这些选项对 Light 和 Heavy 分别设置。初次使用可保持默认值，确认能正常聊天后再调整。

**模型超时** — 一次模型请求允许等待的最长时间。页面单位为秒，范围 `0.001–300`，默认 `300` 秒；文件字段为 `generation.timeoutMs`，单位为毫秒。超过硬超时会结束请求。值过小可能让模型尚未生成完成就失败。

**思考开关与强度** — 控制发送给供应商的推理选项。关闭对应 `none`；开启后可使用供应商默认或选择 `minimal`、`low`、`medium`、`high`、`xhigh`。实际支持范围由模型服务决定；遇到不支持参数的错误，先恢复供应商默认。

**推荐响应时间（建议耗时）** — 对模型延迟的期望，单位为毫秒；表单初始显示 Light `2000`、Heavy `5000`。它用于调度和耗时记录，超过该值不会中止模型请求。不要用它代替超时设置。

## 让回复使用 Light 模型

在“检查 → 模块”找到消息编写模块 `message-composer.default`，把 `modelTier` 从默认 `heavy` 改成 `light`，保存后显式应用。模型名称仍在 Profile 中配置。

## 多供应商与高级参数

网页表单主要编辑一个兼容 OpenAI 的 Provider。需要让 Light 和 Heavy 使用不同供应商时，编辑对应 Profile JSON 的 `ai.providers` 和 `ai.modelTiers`：每个目标都要指定存在且已启用的 `providerId` 和其模型列表中的 `modelId`。

编辑前停止服务并备份文件。完整结构见 [Profile API](../reference/profile-api)。多个供应商方案通过网页重新保存模型表单时，Light 和 Heavy 会重新绑定到当前可编辑 Provider，应先核对是否符合预期。

## 连不上模型时

先检查 API 地址、密钥是否可用、模型 ID 是否正确，再检查供应商支持的思考参数。保存后到生效管理确认应用成功。具体排查见[常见问题](./troubleshooting)。
