# 跨会话消息

## 群聊自然语言投递

在获准入站的群聊中，可以对机器人说“私聊我：会议三点开始”“发到协作群：会议三点开始”或“告诉小红：会议三点开始”。请求仍经过发言门控和 Planner；目标唯一、可达且出站获准时，系统自动生成正文并投递，无需打开管理端再次确认。普通回复和“发到当前群”继续使用当前会话。

Planner 收到两份按本轮冻结的结构化投影。**对话背景**包含当前会话类型、群名称、本轮发言人的显示名、身份识别状态，以及“发言人”“本轮参与者”“被提及的人”等范围内关系；即使没有跨会话意图，也提供给 Planner 和消息编写模块。它不推断朋友、同事等未确认的社会关系，也不读取其他会话的原始正文。

**目标解析**只包含当前 adapter 下与本轮相关的目录项：当前群、末位发言人可达的私聊，以及输入中完整名称匹配或明确提及的人物和群。候选使用临时不透明引用，原始群号、用户 ID 和其他无关目录项不会加入此投影。Planner 只可选择宿主提供的引用，不能生成平台地址。“私聊我”以本轮最后一位发言人为准；好友目录中没有对应账号时不能自动发起陌生人私聊。名称数据没有修改系统规则的权限。

同类型名称重复时不提供可发送引用；人物无法识别、目录不可用、目标不存在或不满足出站白名单时不发送，也不会把原计划正文改发当前群。失败在开发者控制台中表现为关联 turn 的 `target-ambiguous`、`target-unrecognized`、`target-unreachable`、`target-not-found`、`target-unauthorized` 或 `target-unavailable` 等安全原因；可补充明确名称或恢复可达性后重新提出请求。目前不自动向来源群另发失败通知。

跨会话消息编写只接收 Planner 提取的本次发送要求和最小化人物背景，不自动复制来源群历史、Memory 或其他会话正文。只有用户明确要求发送的内容才应进入发送要求。候选引用和授权绑定本轮、账号、连接代次与五分钟有效期；旧引用不能用于新一轮，重启后也不会恢复发送权限。

## 管理端操作

Web UI 顶栏的“跨会话消息”面向已认证的管理者。先加载并选择近期来源对话，再按完整名称、精确号码或描述中的名称查找目标。所有候选都需要明确选择；名称重复时不会自动猜测，描述匹配也只给出建议。

填写允许发送的要求与资料，点击“确认目标与发送要求，生成正文”。系统不会自动复制来源对话的历史或 Memory。正文生成后点击“刷新生成结果”，审阅完整文本，再点击“确认以上正文并发送”。确认成功表示提交了投递处理；实际成功或失败以开发者控制台中的 delivery 终态为准。

## 可达范围与权限

NapCat 通过当前在线连接查询账号、群列表和好友列表。群成员和陌生人不会自动成为私聊候选。启用的任一非 Web adapter 不在线、没有目录能力、查询失败或响应不完整时，整个查询返回不可用，以免遗漏同名候选而误判唯一。

可达不等于已授权。目标还必须满足当前生效 Profile 的 `runtime.outboundAllowlist`。入站获准的群或用户不继承跨会话发送权限；普通聊天内容和 Planner 输出不能直接提供平台投递地址。自然语言路径由宿主复核获胜 Planner 决策及冻结候选；管理端路径仍要求明确确认目标和正文。

候选与批准的有效期为查询后五分钟，绑定 adapter、账号和连接代次。断线重连、账号变化、重启或显式应用配置会使旧批准不可继续使用；请点击“新建请求”重新查询。保存或选择 Profile 不会立即切换策略。Web 保持原有网关认证与白名单特殊策略，不纳入 QQ 候选目录。

## 最终投递检查

目标批准和正文确认都复用统一的 `agent.message.intent.requested`、Composer 和 `core.delivery.requested` 链。管理端路径使用独立 candidate/claim 和批准的冻结上下文，因此不会改变来源 turn 已有的终态。自然语言路径沿用来源 turn 的 claim 幂等键，同一入站消息或决策重放不会生成第二条 intent；自动授权绑定生成的唯一正文，仍执行最终目标存在性、有效期、连接代次和出站白名单检查。

Runtime 在调用平台 transport 前再次检查实际目标。白名单拒绝时不会调用 transport，写入 `core.delivery.failed`，安全错误码为 `destination-not-allowed`，关联 turn 以投递失败关闭。缺少有效目标授权或正文确认时使用 `target-authorization-required`。拒绝事实与普通投递日志不包含目标号码或消息正文，详细目标仅出现在受认证的管理操作和必要的账本事实中。

查询时可见的会话仍可能在发送时无法到达。此时使用原有平台投递失败路径，不将目录查询成功当作消息已发送。
