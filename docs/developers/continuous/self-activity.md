# 自我、状态、活动与关系

`agent.continuity` 将持续自我、当前评价、真实活动和人物约定接入现有 Memory、Model Task 与工具循环。旧 Profile 的模块和自主运行默认关闭。开启模块不会自动赋予工具或出站权限。

本轮范围对应 #323–#327。经历发布到 native Memory 后结束。#328–#332 的方法复用、训练导出及长期运行验收仍独立追踪。隔离测试通过不表示已通过真实群聊、生产环境接管或长期行为验收。

## 第一阶段：真实环境与持续自我

**自我权威 —** `self:kaguya` 的 native Memory 保存角色种子、内部选择、实际经历及能力证据。模板中的人设通过显式导入进入同一修订历史。应用人设资源修改会发布新版本，旧版保留。角色设定不证明现实经历。

**内部来源 —** `agent.continuity.internal-source.v1` 保留真实决策或行动引用。内部选择核对 `agent.continuity.choose` 的实际完成输出。能力证据核对成功行动回执。内部来源使用专用类型，不生成虚假的人类消息。

**资料与产物 —** 资源引用保存地址、读取时间、内容指纹、来源范围和行动回执。默认路径是实际读取资料、保存笔记、独立回读。回读须来自另一条成功回执，且指纹与笔记相同。模型声称完成不替代这些证明。冻结输入保留宿主工具配置版本和已观察的环境租约引用。未观察到的环境状态保持未知，工具提交时仍重新检查权限和租约。

**启用 —** 先启用 native Memory 和持续自我模块。检查角色种子已发布，再配置允许的环境及工具。修改 `.default.hbs` 不会覆盖已有 `.local.hbs`。本阶段只导入种子时，可保持 `autonomous=false`。

**配置升级 —** 启动和离线升级的 `apply` 阶段先完成旧 Lifecycle 迁移，再为完整旧配置添加 `continuity.default`。新模块保持关闭，原有 Profile、模块设置和插件启停状态保留。配置根的 `migrations/continuity-v1.json` 保存迁移前后的插件树与新增配置。中断后重启会从该记录继续，完成后写入 `continuity-v1.complete.json`。配置损坏、缺少其他模块或恢复期间插件树被修改时仍拒绝启动，不重置配置。

**迁移、停用与回退 —** schema 准备过程追加活动投影表，不改写旧原子。旧请求缺少新增上下文字段时继续按旧协议读取。停用保留全部 Memory 版本与来源。回退前关闭自主运行，等运行中的工具到达安全边界。回退到不认识 `continuity.default` 的旧版本前，须停服并使用升级前配套的配置备份，保留迁移记录供再次升级。不要删除来源和回执，也不要用旧二进制继续驱动未结束的新活动。

## 第二阶段：当前状态与自主活动

**主观字段 —** 模型只能提出关注对象、兴趣及理由、情绪评价和社交意愿。宿主保存评价版本、依据、时间和策略。默认三十分钟过期，可配置。过期只改变有效性，不产生新的心情。实际专注依据主活动位置和工具进度。

**共同输入 —** Router 在新情境中冻结自我、状态、开放活动、资源及宿主配置。Light 与 Heavy 读取同一冻结版本。活动选择在状态评价保存后再次冻结输入。后续变化不修改旧 Prompt。

**活动 —** 愿望、请求、已接受约定和候选计划使用不同类型。执行状态为候选、进行、等待、暂停、完成、放弃和失败。外部结果另存为未知、部分完成、已核对或失败。投影更新与追加版本事实在同一事务提交。

**协调 —** 自主活动共用一个主活动位置。普通聊天和独立只读工具不取消阅读。聊天需要主行动工具时，在安全边界暂停原活动，保留步骤、下一步、产物和回执。聊天释放位置后，原保存点进入等待。后来的人工暂停优先。过期或已终止的聊天占用会在重启时释放，旧外部行动不会因此重发。

**预算 —** 以 Agent 时区每天最多二十四次新增自主模型调用。评价、选择、执行回合及结构恢复都在实际模型尝试前计入。重启、重复事件和重试不会清空额度。改变时区会保守继承已用额度。普通聊天及原有整理链不使用这个额度。预算不足时等待下一当地日期。单次工具最多五分钟，其余限制沿用原工具预算。

**触发 —** 有意义的新事件、明确更正、活动结果、管理操作和有效到期条件可以触发评价。评价允许无变化。纯生命周期节拍不调用模型。下一次检查使用持久化 one-shot，不补发离线期间的节拍。

**恢复 —** 原 Model Task、工具运行、意图和回执均从账本复用。未知写入阻止新的活动写入。`activity.inspect` 读取原回执，`activity.reconcile` 重新检查原工具策略与环境后，仅调用原 provider 的核对接口。核对仍未知时继续等待或交给人工处理。迟到结果保留在原活动，不恢复已放弃活动。

**启用 —** 配置 `agent.continuity` 的 `autonomous=true`、来源范围和状态有效期。运行时要求 native Memory 及批准的执行工具。Linux 工具继续使用既有环境绑定、租约与宿主授权。跨会话约定只在原来源范围内读取及执行，不能扩大环境能力。

**迁移、停用与回退 —** 启用不复制另一份自我。停用停止新增自主调用，并请求运行中的活动在安全边界暂停。重新启用从保存点进入等待，人工暂停保持暂停。旧活动、未知外部结果、预算和资料产物继续可检视。回退前核对所有未知写入，不能通过重新建活动规避旧操作身份。

## 第三阶段：人物关系与承诺

**认识与归属 —** 复用人物 ID、native Memory 节点和来源证明。本人自述、第三方描述、实际观察及推断沿用现有 `evidence.basis`。Kaguya 的关系印象标为推断。对方反馈另加明确标签和反馈目标引用。共同经历通过实际活动关联的人物 ID 检索，重名不合并身份。

**接受与执行 —** 接受或延后处理由实际 Heavy 决策和当前原始请求证明。接受后创建承诺活动。执行、资料核对、消息投递和对方反馈分别记录。关系记忆只引用活动，不维护第二套执行状态。发送成功仍可能没有履约反馈，对方沉默保持未知。

**投递 —** `activity.deliver` 只能面向当前已接受约定的原请求目标。工具调用、计划、消息桥接、行动准入和最终出站检查沿用现有流程。目标不能由模型自由指定。已提交或结果未知的自主投递不重复发送。

**更正 —** Memory 修订、来源撤回和身份拆分在发布事务中检查活动依赖。受影响的未执行计划进入等待并要求重评。正在执行的活动请求安全暂停。已发生的行动和投递不被删除。已完成的执行历史不会因重评自动重开。

**管理界面 —** 持续活动模块展示来源范围、主观状态有效性、预算、进度和下一次检查。人物页展示当前可读认识、共同经历及开放约定。来源按钮进入原始记录，完整历史保留在 Memory 与 Information 检视中。未评估、未知、过期、等待和失败分别显示。

**管理接口 —** `GET /api/v1/continuity` 按指定范围读取。`GET /api/v1/continuity/people/:personId` 按相同范围读取人物上下文。`POST /api/v1/continuity/activities/:activityId/control` 接受暂停、恢复或放弃，必须包含 `scope`、UUID `operationId` 和 `expectedRevision`。管理认证沿用现有 Bearer token。重复原操作返回原结果，版本冲突返回 409。结果未知时先刷新核对，再重试原操作。

**启用、迁移、停用与回退 —** 人物与关系不另建身份库。已存在人物继续使用原 ID。模块关闭后，来源、开放承诺、投递和历史仍保留。关闭自主运行不表示撤销已经接受的约定，管理员需核对并明确处理。回退保留活动引用，不能把工具成功改记为对方确认。

## 验证与证据边界

程序回归分别使用 PGlite 和随机 schema 的真实 PostgreSQL。关键测试不得跳过。测试覆盖持久预算、重复事件、版本竞争、主活动互斥、安全暂停、手动暂停优先、过期、重启、隐私隔离、笔记回读、实际投递和原请求者反馈。

联网验收入口为 `scripts/evaluate-continuity.mjs`。必须显式提供输出目录。生产模型模式还需指定含已配置模型的 Profile。脚本只创建独立 PostgreSQL schema 和独立 Linux 容器，不连接平台 transport。它保留全部 Model Task、失败、usage、冻结输入和产物。缺少价格配置时费用保持不可用，不估算金额。

此入口使用固定公开 RFC 和受限的 Docker 工作区提供环境证据。它不替代生产 rootless Linux broker、真实平台交互或长期行为验收。模型是否正确理解人物、拒绝是否自然、约定是否被合理接受，需要逐例评价，不能从协议完成率推导。
