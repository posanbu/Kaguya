# 记忆形成与整理

Memory 形成由 `memory.native` 统一运行。契约和检索边界见 [Memory 模块边界](../memory.md)。

## 来源与批次

身份解析完成后，同一会话的真人文本进入持久化来源队列。默认达到 8 条或等待 60 秒触发，单批最多 24 条。认领、批次内容和终态保存在数据库中，模型请求沿真实来源冻结。

定时到期事件只引用调度请求。Memory 沿调度请求的原始来源读取运行上下文，并显式传给整理请求，不依赖到期事件直接携带上下文。重启后仍使用这条来源链。已认领但尚未创建整理请求的批次，在后续有效触发时继续处理，不重新认领来源。

旧版队列或未完成批次缺少来源类型、参与者和引用字段时，领取阶段从原始入站消息或成功投递记录恢复这些字段。来源和批次在同一事务内更新，保留原 ID、正文和时间。被提及或被引用的账号没有已保存的身份依据时，人物归属保持未知。原始记录不可用或类型不受支持时拒绝恢复，不猜测来源。

批次是处理单位，不是经历单位。模型可以补充已有经历、修正结论或返回空结果。来源缺失、作用域不符、版本冲突和手动锁定都会阻止自动发布。

## 层级与修订

同一对象和作用域最多有一个有效的 level 0 摘要。情境冻结前，Memory 根据实际入站来源补齐最小人物与会话摘要，不必等待八条消息。更具体的记录使用较大的 level，通过 `summarizes` 连接。修订保留原节点 ID，增加 revision。节点、边、全文索引和审计记录原子提交。

修改细节但没有同步更新的祖先摘要会失效，退出固定注入。自动形成不覆盖手动锁定正文。模型输出必须区分自述、观察和推断，不能把旁观者猜测作为当事人的确定事实。

例如，B 先说“戒了咖啡”，后更正“晚上不喝，白天还喝”。整理应更新该经历及相关摘要，保留两次来源。C 的相反猜测应保留归属，不能直接替代 B 的自述。此类归属质量仍需要模型场景评估，结构校验不能证明推断正确。

## 固定摘要与召回

人物和会话的最小摘要在首次实际交流时补齐。基本人物关系、背景和群聊属性随来源整理逐步修订。适用的 level 0 无条件注入。它们不经过关键词、embedding 或 topK 筛选。具体经历可由文本、向量或显式引用命中，再沿图展开。

形成过程失败时保留原始来源和可见的失败批次。没有派生记忆不表示事件没有发生。旧回合始终读取保存的版本，不用后来的修订改写过去的模型输入。

## 当前边界

来源适配主要覆盖已归一身份的真人文本、成功投递的自身消息，以及 QQ 插件提供的文字上下文推断。工具、音频、图像和外部来源撤回需要专门的来源契约，不能把意图或视觉猜测写成已经发生的经历。

索引可以自动重建。模型形成质量、人物归属和长期整理质量需要独立评估，不以 schema 验证或检索功能清单代替效果证据。

人物细节的 `evidence` 区分本人自述、第三方描述、观察和推测，并保存观察时间、来源范围及明确的有效时间。一次情绪不应变成长久性格。学历和职业不能从“赶论文”等模糊表达推定。普通稳定背景只有在本人于群聊明确表达时才可共享，私聊和限定信息保留来源范围。

Heavy 可以在已有交流中自然了解更多，但不向 Memory 下达资料收集目标。新的原话再次进入来源队列，画像仍由同一形成流程整理。主动补查及其冻结结果见 [人物画像与主动补查](../memory.md#人物画像与主动补查)。
