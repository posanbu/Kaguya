# 记忆形成与整理

Memory 形成由 `memory.native` 统一运行。契约和检索边界见 [Memory 模块边界](../memory.md)。

## 来源与批次

身份解析完成后，同一会话的真人文本进入持久化来源队列。默认达到 8 条或等待 60 秒触发，单批最多 24 条。启动和每 60 秒的维护还会扫描原始账本，补收身份流程尚未交付的真人文本及成功投递消息。未知人物保持会话归属，不依赖前台回复。认领、批次内容和终态保存在数据库中，模型请求沿真实来源冻结。

每条来源保留原 Information ID，并登记确定 ID 的 `memory.native.source.v1` 正规来源。入站正文必须匹配原文；自身消息必须匹配成功投递和对应请求。正规来源按完整平台、适配器和目的地隔离。原始缺口的排除或待恢复原因保存在 `memory_native_source_gaps`，维护状态可在 Memory status 的 `recovery` 阶段查看。

Memory 使用独立的 `memory.native` observation 消费进度。证明绑定已保存的形成请求、正规来源、原始证据和实际成功终态。尚无对应证明的 Memory 缺口按单条来源分配，后续不同批次可分别替换；已覆盖的连续来源仍正常分页。旧完成批次恢复时补确认，不重新生成。失败批次不推进连续水位；较后批次可以完成，水位等待前面的缺口闭合。正规注册次序可能与旧来源队列不同，冻结边界取本批全部正规来源的最大注册位置。

定时到期事件只引用调度请求。Memory 沿调度请求的原始来源读取运行上下文，并显式传给整理请求，不依赖到期事件直接携带上下文。重启后仍使用这条来源链。已认领但尚未创建整理请求的批次，在后续有效触发时继续处理，不重新认领来源。

旧版队列或未完成批次缺少来源类型、参与者和引用字段时，领取阶段从原始入站消息或成功投递记录恢复这些字段。来源和批次在同一事务内更新，保留原 ID、正文和时间。被提及或被引用的账号没有已保存的身份依据时，人物归属保持未知。原始记录不可用或类型不受支持时拒绝恢复，不猜测来源。

批次是处理单位，不是经历单位。模型可以补充已有经历、修正结论或返回空结果。来源缺失、作用域不符、版本冲突和手动锁定都会阻止自动发布。

版本冲突保留原请求、模型结果和拒绝终态，并创建唯一后继批次，重新冻结当前修订。另一个 pending 批次暂时占据该范围时，维护会补建后继。手动重试同样保留原失败状态。空结果和无变化结果成功确认消费范围，不生成虚假的节点修订。

## 层级与修订

同一对象和作用域最多有一个有效的 level 0 摘要。情境冻结前，Memory 根据实际入站来源补齐最小人物与会话摘要，不必等待八条消息。更具体的记录使用较大的 level，通过 `summarizes` 连接。修订保留原节点 ID，增加 revision。节点、边、全文索引和审计记录原子提交。

修改细节但没有同步更新的祖先摘要会失效，退出固定注入。自动形成不覆盖手动锁定正文。模型输出必须区分自述、观察和推断，不能把旁观者猜测作为当事人的确定事实。

新冻结形成的经历保存 `experience.state`，初始值为 `open`，策略标识为 `experience.v1`。模型可以依据明确来源提出 `sealed` 或重新打开；关闭状态不把后来的更正锁死。这里没有按沉默时长自动推定经历结束的规则。管理端通过同一 publications 接口提交 `correct`、`seal`、`reopen`、`merge` 或 `split` 操作。新形成请求持久保存 `experience-operations.v1` 策略。自动合并和拆分要求冻结输入版本、明确的输入／输出节点及完整来源覆盖；服务端派生前驱与来源归属。旧请求按原输出 schema 恢复，管理端仍可提交相同事务操作。归档输入与发布输出在同一事务中完成；输出记录 predecessors，保留原作用域和合法所有者，并覆盖输入及其证明依赖中的来源。predecessors 仅记录审计沿革。服务端按各输出实际分配的来源保存 proofOwners，保留这些证据的归属；撤回或身份拆分只影响依赖相关证据的输出。输入归档或共享同一前驱本身不使其他分支失效。proofOwners 由存储层派生，普通修订、seal、reopen 和 correct 不接受客户端覆盖；省略或清空该字段仍保留已有映射。移除来源后，读取只检查当前 sourceIds 的交集；重新加入同一来源会恢复原归属约束。拆分输出仅继承实际分配的来源。

所有 native 类型和层级共用服务端 `metadata.proofOwners`，已有 `experience.proofOwners` 继续作为失效依赖；旧派生 owner 映射本身不证明来源身份已完整收集。新建和修订都会核验全部当前来源，包括旧节点中没有证明的来源。发布事务从持久化来源、原始入站消息的真实账号绑定或既有服务端证明推导归属；无绑定入站消息保留实际会话归属，客户端无需填写。无法验证的来源返回 `memory_source_proof_missing`。拆分只能继承输入中已有的来源证明，节点 owner 本身不能替代来源归属。

正规化在原子中保存 `sourceProofVersion` 和 `sourceOwners`，固定原始账号的全部身份依赖，包括已拆分的身份。旧节点读取按指定 source ID 补查发布上界内的完整来源证明，只投影 ID 和归属。只有单一 owner、缺少完整证明标记的旧 canonical 不会填平无证明节点的缺口。当前读取与显式历史读取使用相同上界。正规来源与 Memory publication 共用全局提交锁，避免迟提交来源填入已冻结的上界。没有节点证明、且上界内没有正规来源的旧内容暂不进入上下文；仅有旧来源队列表记录或稍后补写的正规 Atom 不会改变原 cutoff。补证不改写节点、旧 publication、输入哈希或已冻结快照。相同 operation 的重放先返回原保存结果。

人工发布可以追加 `source-withdrawal` 或 `identity-split` 失效事件。失效只沿 `summarizes`／`derived-from` 的证明依赖传播，普通话题或人物连结不传播。固定摘要、人物候选、显式引用、全文、向量候选复核及图展开共用这条规则。形成输入排除已撤回或身份拆分的内容；发布前再次检查原依赖链，防止旧结果通过删除依赖边重新发布。

例如，B 先说“戒了咖啡”，后更正“晚上不喝，白天还喝”。整理应更新该经历及相关摘要，保留两次来源。C 的相反猜测应保留归属，不能直接替代 B 的自述。此类归属质量仍需要模型场景评估，结构校验不能证明推断正确。

## 固定摘要与召回

人物和会话的最小摘要在首次实际交流时补齐。基本人物关系、背景和群聊属性随来源整理逐步修订。适用的 level 0 无条件注入。它们不经过关键词、embedding 或 topK 筛选。具体经历可由文本、向量或显式引用命中，再沿图展开。

形成过程失败时保留原始来源和可见的失败批次。没有派生记忆不表示事件没有发生。旧回合始终读取保存的版本，不用后来的修订改写过去的模型输入。

每次新冻结在同一 REPEATABLE READ 快照内读取 Memory 已提交发布上界，并保存为 `cutoff.publicationPosition`。它独立于全局 Information 注册位置：较早分配序号、尚未提交的发布不会进入冻结。当前读取使用同快照中的现态和有界候选查询；显式历史读取重建指定上界内的节点与边。历史索引缺失时使用对应历史正文。跨范围失效依赖只在内部核验，可返回正文仍按当前读取范围过滤。

发生时间不晚于本次 asOf、尚未成功形成的最新原话可以作为 `pendingEvidence` 进入冻结，保留 ID、归属、范围和时间。数据库最多检查最新 101 条、返回 100 条，每条正文最多 1200 字；冻结给原话最多 2000 字，并计入既有动态预算。`truncated`、`originalCharacters`、`evidenceHasMore` 与 `evidenceOmittedInformationIds` 明确表示裁剪和省略，完整原文仍可按来源 ID 从账本补读。最终提示另按 UTF-8 字节预算裁剪动态原话，不回写冻结正文。

无 `cutoff` 的历史形成请求继续使用原 v1 输出 schema 和渲染路径，重放保持原模型任务身份。新字段均为可选字段，不给旧 publication 补默认值；既有 operation ID、输入哈希和 revisions 保持原样。

## 升级与回退

启动准备 schema 只增加来源缺口表、批次 predecessor／retry_requested 字段与唯一索引，以及 native 发布位置／失效事件的局部索引。`memory_native_epoch.source_after` 仍由首次启用时的注册位置决定；重启、重试、新 observation 消费者及重复准备 schema 都不更新它。epoch 前的旧证据不会被维护补收，epoch 后晚登记的旧时间消息按注册位置接纳。

升级前保存数据库备份。代码回退前停用 Memory 自动形成，并保留升级后的原始账本、发布记录和备份；旧程序不能承担新增失效语义或新冻结请求的消费。修复后使用支持这些契约的版本恢复。不要删除新记录、清空消费进度或重置 epoch 来实现回退。

## 当前边界

来源适配主要覆盖已归一身份的真人文本、成功投递的自身消息，以及 QQ 插件提供的文字上下文推断。工具、音频、图像和外部来源撤回需要专门的来源契约，不能把意图或视觉猜测写成已经发生的经历。

索引可以自动重建。模型形成质量、人物归属和长期整理质量需要独立评估，不以 schema 验证或检索功能清单代替效果证据。

人物细节的 `evidence` 区分本人自述、第三方描述、观察和推测，并保存观察时间、来源范围及明确的有效时间。一次情绪不应变成长久性格。学历和职业不能从“赶论文”等模糊表达推定。普通稳定背景只有在本人于群聊明确表达时才可共享，私聊和限定信息保留来源范围。

Heavy 可以在已有交流中自然了解更多，但不向 Memory 下达资料收集目标。新的原话再次进入来源队列，画像仍由同一形成流程整理。主动补查及其冻结结果见 [人物画像与主动补查](../memory.md#人物画像与主动补查)。
