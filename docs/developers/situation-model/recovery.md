# 更新与恢复

新信息改变当前可知状态。历史证据、旧请求清单和已经发生的结果保持不可变。

## 更正与行动检查

更正引用被修正的证据。尚未开始的相关行动进入重新检查或被替代状态。无关行动继续执行。失效判断需要保留触发证据和规则。

取消与发送竞争时，通过持久状态比较确定谁先获得执行权。请求取消只表示请求已经提出，执行方确认后才能记录取消成功。

已执行的部分保留实际结果。需要补充或补偿时创建新行动，并引用原行动。不能修改旧结果，假装副作用从未发生。

## 结果未知

请求已发出但确认丢失时记录 unknown。优先使用查询、回执和执行方幂等能力核对。缺少失败记录不证明未执行，未知状态不能直接重新进入发送队列。

重启时把仍显示执行中的外部副作用恢复为未知状态，或按能力专属恢复协议核对。模型失败、读取失败和投递未知分别显示，不统一解释为自然沉默。

## 事务与进度

证据接纳、持久待处理范围和必要投影需要原子提交，或由唯一事实幂等重建。在线广播只是加速路径，恢复需要扫描持久任务。

观察形成失败不推进观察进度。模型失败复用原清单。后续结果已经成功处理时，模型步骤进度再单独推进。失败段不能被后来完成段越过而消失。

检查点提交与旧轨迹归档共同生效。崩溃不能留下“旧轨迹已隐藏，但新检查点不存在”的状态。

## 物理会话轮换

安全点需要没有未闭合的原生工具交互，且当前步骤已经终结。轮换先保存逻辑 Agent 绑定、检查点和开放任务，再创建新物理会话。

外部后台任务可以保持自己的行动身份继续运行。新会话通过结构化任务状态理解它们，不在新会话中伪造旧工具调用或成功回执。

恢复使用唯一逻辑 Agent 绑定，防止两个物理会话同时成为主行动线。旧会话的迟到输出必须经过有效性检查。
