# 上下文装配

一次请求使用稳定规则、连续性检查点、最新情境帧和近期行动轨迹。模型消息的物理角色由宿主映射，领域中的情境更新不因此变成人类指令。

## 更新与冻结

输入先进入持久证据账本，再更新情境投影。高频接收不自动调用模型。调度器可以合并唤醒，也需要持久保存延期条件和待处理范围。

开始模型步骤前，装配器读取同一提交边界上的情境、召回和行动状态，保存请求清单。冻结后发生的变化只影响后续清单。相同步骤身份的重试返回原清单。

模型常驻上下文只保留当前检查点和当前情境帧。旧版本留在审计存储，不通过在 Prompt 末尾增加“此前内容已过期”来代替真正替换。

## 总背景与当前情境

背景包含本次完整消费的连续信息范围，当前情境补充相关历史。两者展开同一证据时按身份去重。历史补充不重复推进观察水位。

接收顺序用于发现未处理范围。发生时间用于理解迟到消息和有效期。分页上限不能直接变成成功水位。装配器保留 continuation，处理后续页面。

选择策略及预算随清单保存。可选背景被省略时，缺失状态对下游可见。必需未读信息放不下时，形成较小的完整范围，或阻塞请求，不能裁掉正文后确认全部已读。

## 变化说明

变化说明列出相对于前一个已完成模型步骤的新增证据与失效引用。多次情境更新合并到一个字段。未完成或失败步骤不推进这个基准。

变化说明只是导航。当前情境和行动依据仍给出必要内容，不能只留下模型无法解释的一组版本 ID。切换情境时同时声明新的当前情境身份。

## 预算

预算需要覆盖规则、工具定义、必要运行约束、检查点、情境和原生工具轨迹，并为输出预留容量。宿主缺少可靠容量信息时必须显式配置，不能假设上下文无限。

先去掉重复展开，再缩减可选背景和无关召回，最后归档已闭合的旧行动片段。必要状态仍超预算时阻塞，并保留可恢复任务。检查点本身也需要预算，不能积累所有历史的逐条摘要。

工具调用和结果按完整单元保留。原生协议与领域行动记录互相引用，不能把一个原生调用的结果留在上下文中，却移除对应调用。
