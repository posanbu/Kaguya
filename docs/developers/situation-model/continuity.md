# 行动连续性

整个 Agent 维护一条主行动线。当前情境可以变化，行动身份、待办和实际结果保持连续。

## 保留当时的依据

每个行动绑定产生它的请求清单和情境帧。行动依据记录展开必要证据，保存证据身份与原情境。后来更新情境不会改写这些内容。

执行前检查行动是否被替代、依赖是否仍成立以及权限是否有效。只因无关消息到达就取消工作，会使长期任务持续饥饿。明确停止、更正与权限变化需要独立处理。

行动结果成为新证据，再进入后续情境。模型提出行动不等于执行成功，工具完成也不等于结果已经被后续步骤处理。

## 近期轨迹与检查点

近期轨迹保留完整行动单元。未完成任务、未知结果、未兑现承诺和未闭合工具交互保持可见。已完成行动仍保留一个可配置的近期窗口。

归档以闭合片段为单位。只有结果已处理、工具已配对、相关依赖已保存的片段可以移入检查点。存在较早未知行动时，允许归档其他独立片段，不要求整个历史前缀全部完成。

检查点记录前一版本与覆盖范围，保留有关的结果摘要、开放任务、承诺和等待条件。执行状态从账本确定性生成。可选的模型叙述不能覆盖这些字段。

检查点发布和轨迹归档在同一事务中完成。恢复只使用已提交版本。被归档的原文仍可查询，并能沿行动、情境帧和证据回溯。

## 跨情境与长期任务

群 A 的查询执行期间，群 B 可以更新总背景。调度器之后可以关注群 B，但 A 的任务和结果仍存在于主行动线。工具结果明确关联原行动，不能被归入后来选中的场景。

长任务可以归档已经闭合的子段，同时保留尚未完成的状态和必要证据。连续性要求可恢复的语义状态，不要求每次请求重放整个工具输出。

等待拥有持久期限或明确条件。重启后恢复同一等待身份，不创建重复 timer。预算或外部条件导致阻塞时，同样保留任务与原因。

## 历史查询

按行动身份、范围和情境查询原始行动与证据。旧帧按原版本返回，不用最新召回替代过去使用的记忆。查询结果是有来源的背景，不修改已确认进度。

物理模型会话可以在安全点轮换。逻辑 Agent、检查点和行动身份继续使用。原生工具调用尚未闭合时不得轮换，避免伪造或丢失调用结果。
