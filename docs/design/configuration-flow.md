# 配置流程设计

这页供界面维护者查阅。实际操作和字段含义见[配置概览](../guide/configuration)。

## 区分编辑对象与运行对象

顶栏选择器只切换编辑上下文。创建、编辑和保存 Profile 不应暗中更换运行实例；“设为当前”和“应用当前配置”分别负责选择与执行。

页面同时呈现当前选中和当前生效的 Profile，帮助用户确认保存后的内容是否已经运行。模块设置、身份资源和模板属于工作区，编辑时应明确它们不随 Profile 切换。

## 明确操作后的状态

保存成功表示文件已写入。显式应用会预检并切换实例，期间消息入口短暂暂停；成功后显示已生效，失败则展示原因和可恢复操作。

进程参数变更需要重启，模板编辑也需要重启。界面应把这些情况与可直接应用的模型、Memory、平台及模块参数区分开，详见[配置生命周期](../developers/configuration-lifecycle)。

## 在操作处解释错误

字段无效时把错误放在对应控件旁，并保留输入。版本冲突时允许用户保留草稿、重新读取后再修改，不能静默覆盖别人的保存。

认证失效时引导用户打开当前终端的新访问链接。配置文件损坏时保留原数据并说明具体问题；不以自动覆盖文件代替恢复操作。

## 给使用者提供直接入口

常用字段链接到[模型配置](../guide/models)、[QQ 接入](../guide/napcat)或[模块配置](../guide/modules)。运行错误链接到[常见问题](../guide/troubleshooting)，不要求用户先阅读设计说明。
