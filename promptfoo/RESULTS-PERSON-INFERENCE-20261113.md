# 人物认识：首轮实现与合成对照

首轮代码已实现多轮人物推断、来源约束和后续使用规则。程序验证通过，但模型对照尚未通过行为验收。现有结果不能证明稳定提升。以下是 Codex 对实际输出的逐例审阅，尚未经过用户或独立人工评价。

## 条件与证据

运行日期为 2026-11-13。基线为主线 `02ab48e0d8850f7eb07d69a36a5bece79f3a4c1a` 的默认模板，改进组使用本次默认模板。运行代码相同，忽略 local 覆盖。两组 Light 与 Heavy 均调用现有 profile 的 `deepseek-v4-flash`，温度为 0。情景、来源顺序和非语义请求 ID 保持一致。

七个合成情景各组计划十次形成、十个问题。形成使用生产 Prompt、来源校验和事务发布。回答使用实际冻结读取和补查。评测按阶段强制形成，简化回复接续，不复现生产调度和结构化输出修复，也没有连接群聊或投递消息。

原始结果保存在被 Git 忽略的 `.data/evaluations/person-inference-20261113/`。每个结果保留实际模板哈希、场景哈希、模型输入、输出、用量、失败及部分进展。`summary.json` 汇总分母。实际模型请求包含的模板版本以各条结果的 `templateDigest` 为准。

- **初始配置**：每次最多 2048 token，未发送推理强度。两组各七个情景全部失败。多数请求用完额度后未返回完整正文。该轮用于识别评测设置问题，不能评价人物理解。
- **Profile 推理设置**：每次最多 8192 token，Light 使用 `minimal`，Heavy 使用 `high`。改进组完整完成 3/7 个情景，基线完成 2/7。改进组成功发布 7/9 次形成尝试，基线为 5/8。两组均计划十次形成，较晚阶段因前序失败而未尝试。
- **同为较低推理强度**：每次最多 8192 token，两组 Light 和 Heavy 都使用 `minimal`。改进组完整完成 3/7 个情景，基线完成 4/7。这些数字衡量流程完成，不能作为语义质量分数。

最后一轮中，改进组成功发布 7/10 次形成尝试，基线为 6/8。按十个计划阶段计算，分别为 7/10 和 6/10。改进组有六个问题的表达流程结束，基线有五个，分母均为十个计划问题。这里将消息正常结束或 `silent` 视为流程结束，不能据此判定问题已得到恰当回答。

最后一轮改进组调用 22 次、记录 108122 token。基线调用 17 次、记录 69255 token。两组因失败而执行了不同数量的阶段，不能据此推断等量任务的成本差。所有调用均有返回的 token 用量，但没有实际计费回执。不同推理设置只做独立报告，不合并成提示词收益。

## 最终模板的针对性复查

前述输出中出现过把 `scope` 字符串写成数组或表达式的错误。本次将其字符串要求写得更明确，并只复查“隐含科研背景”和“明确身份更正”两个已知失败场景。使用与较低推理轮相同的模型、8192 token 上限和 `minimal` 设置。

改进组完整完成 1/2 个情景，基线为 0/2。成功情景中，改进组最初判断“看起来是在读研”，收到“研究助理、不是学生”的明确更正后，将人物认识和后续回答改为研究助理，并保留晚上不喝咖啡这一条件。旧冻结重读仍保持原版本。

另一个改进情景在形成成功后返回空回复。两项基线均被范围或证据校验拒绝。该复查针对开发中已见失败，属于调试样例，不是独立测试集，也不替代七情景的完整对照。它提供了一条实际模型完成推断、更正、后续使用的证据，仍不足以证明稳定收益。

## 逐例检查

- **隐含科研背景**：改进组形成了科研相关的暂定认识。Profile 轮回答“阿岚看起来是在做科研实验的”，并承接实验重跑及周五汇报。较低推理轮仍出现“像在读研”的更具体猜测。该身份未经本人确认，具体程度仍需约束。两轮的后续阶段均有失败，未完成整个情景。
- **线索不足**：两组都能判断近期赶论文，并保留具体身份未知。改进组先回答近期事项，减少了“只是群里的账号”这一表层描述。该样例没有证明广泛的身份推断收益。
- **第三方与玩笑**：较低推理轮两组都正确区分阿岚排错和小夏准备网站演示，也没有把“院士”的调侃写成真实身份。未观察到明确的改进组优势。
- **历史与当前活动**：较低推理轮基线完成了从改住宅方案到休假拍照的更新。改进组正确回答第一阶段，但第二次形成输出非法 JSON，未验证其后续更新。
- **明确身份更正**：程序测试验证了修订与旧版本读取。完整对照仍有非法 JSON 或回复结构错误。最终针对性复查完成了一条实际更正链，整体稳定性仍未验收通过。
- **同名人物**：改进组能将实验、组会和投稿归到被明确提及的小林，没有混入另一位小林的网站项目。基线在相关轮次失败，不能将该单例当作稳定收益估计。
- **私聊隔离**：程序测试通过。Profile 轮两组完成，群聊冻结未包含私聊推断。较低推理轮改进组补查后未形成合法回复，基线选择沉默。没有发现群聊模型输入泄露该私聊，但仍需区分范围正确与回答质量。

## 程序验证与当前结论

类型检查、lint、构建、架构检查、文档检查和离线提示词检查通过。全量回归为 229 个文件通过、2 个文件跳过，2201 项通过、72 项跳过。新增检查覆盖原始来源形成、修订、范围隔离、补查额度、旧冻结版本、相同条件对照和评审说明不进入模型输入。

关键测试在真实 PostgreSQL 可用的条件下完成，共 1490 项通过，零失败、零跳过，并通过 `check-critical-test-report.mjs`。其中人物推断、依赖撤回和旧版本回读同时在 PGlite 与 PostgreSQL 上通过。最后调整的评测参数检查另跑九项，全部通过。仓库全量格式检查仍被未修改的模板 partial 和存量格式问题阻止，本次修改文件单独检查。

结论是：实现已允许并要求有依据的人物推断，实际样例也出现了综合理解。但现有模型的空输出、非法 JSON、范围字段错误及推断具体程度仍限制效果。原始失败保留在比较分母中。当前不关闭 #248/#278，也不将本轮合成输出记为真实群聊验收。自主活动继续按 #324/#326 的后续顺序实施。
