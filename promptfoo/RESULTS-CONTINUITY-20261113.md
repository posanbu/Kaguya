# 持续自我与活动验收记录（2026-11-13）

本轮以已合入 #333 的 `c183ddec298177b5034ab2994cf1bed6099c57a6` 为基线，实现 #323–#327 的贯通流程。代码验证、实际环境效果和模型行为分别记录。本记录不关闭上述 issue。

## 实际模型与失败分母

使用已配置 Profile 的生产 resolver、Model Task、生成参数和结构恢复路径。light 与 heavy 均为 `deepseek-v4-flash`。light 的 reasoning 为 `minimal`，heavy 为 `high`，硬超时均为 300000 ms。没有为评测降低推理强度或另选模型。

所有联网模型场景合计创建 16 个 Model Task 请求。14 个完成，2 个在实际调用前被预算拒绝。实际发生 14 次模型调用，没有观察到结构恢复重试或服务商失败。累计 usage 为输入 78324 tokens、输出 4835 tokens，共 83159 tokens。未配置价格，金额不可用。

保留的场景如下：

- **默认角色种子，空活动**：2 次调用。模型选择等待，没有发生工具行动。不能把它计为阅读完成。
- **明确标注的合成 HTTP 兴趣**：6 次调用。模型创建阅读活动，实际读取公开资料，保存笔记并独立回读。活动进入完成，外部结果标为已核对。
- **探索性状态对照**：3 次调用，另有 1 次预算拒绝。三个可调用案例均返回符合当时结构 schema 的 JSON，但“愿意交流”案例编造了活动 ID。宿主若提交该选择应拒绝它。不能把结构合法记为选择正确。连续案例的剩余预算不同，因此不用于估计状态的因果效果。
- **相同初始预算的独立状态对照**：专注、愿意交流和想独处各调用 1 次。三者均选择继续已有阅读，并引用正确活动 ID。预算不足案例在调用前被宿主拒绝，没有外部模型请求。

发现活动 ID 问题后，生产选择 schema 改为只接受冻结输入中的开放活动 ID。非法 ID 进入原有结构恢复路径，恢复尝试也计入预算。较早的失败保留，不用后续通过替换分母。默认角色种子与合成兴趣的证据不同，不构成提示词效果的受控对照。

## 实际 Linux 阅读效果

资料为 [RFC 9110 原文](https://www.rfc-editor.org/rfc/rfc9110.txt)。读取、保存和回读使用独立 Linux 容器及受限工作区，行动经过生产原生工具循环与持久回执。没有连接平台 transport。

- 公开资料为 502941 字节，内容 SHA-256 为 `21c1cdce6ab0e5509b04d84a28000836c7a087cf786efe6f04877ebfff47232a`。
- 模型只收到有界正文。它在笔记中明确标注截断，区分目录与实际可见正文，没有把整份文件下载成功说成全文已读。
- 中文笔记为 3656 字节。保存与独立回读的 SHA-256 均为 `b9d7f29433111f13a3264d20f38d786a6c52dc32d2fe322df7f481faa1e2551d`。两次操作使用不同回执。
- 角色种子、实际内部选择和实际活动经历均有 native Memory 修订记录。没有建立虚假的人类消息。

确定性模型另跑了一次相同 Linux 路径，读取、保存、回读均发生。它只证明程序链可执行，不计入真实模型的行为成绩。

Linux 进程级故障检查包括断网、内容变化、部分写入、取消和重启，5 项通过。这些检查与阅读主链分别记录。它们不证明生产 rootless broker 的全部故障路径已经通过。

## 人工逐例评价

**协议完成 —** 实际发生的 14 次调用均有终态与 usage。两个预算拒绝保留为未完成请求。活动 ID 的语义错误另计，不能被 JSON 通过率掩盖。

**认识合理性 —** 阅读笔记能够区分初始兴趣、真实读取范围和未读内容。状态对照中，“专注”和“愿意交流”案例仍加入了未经来源支持的章节号。这是无依据的具体化。三个状态均选择阅读，在没有插话的场景下可以成立，但未证明主观状态会稳定改变社交选择。

**表达自然度 —** 实际阅读输出是执行说明，较长，不能代表日常聊天。自然拒绝、延后问题、接受约定是否合适，以及人物关系是否自然，尚未取得真实模型交互证据。

**执行结果 —** 一次合成兴趣场景完成实际阅读、笔记保存、回读和经历发布。真实模型没有执行平台投递。承诺接受、实际消息投递、原请求者反馈、偏好更正和私聊隔离由确定性集成测试验证，不能据此宣称真实交流效果。

修改文件的格式检查通过。全仓格式检查仍包含原有格式问题，并因未改动的 `heavy.memory.default.hbs` 使用 Handlebars partial 而报解析错误。类型检查、代码规范、构建、架构、离线 Prompt 回归与文档链接检查均通过。启用、迁移、停用和回退说明见[开发文档](../docs/developers/continuous/self-activity.md)。

## 复现与限制

先构建仓库。`scripts/evaluate-continuity.mjs` 用于实际 Linux 场景，`scripts/evaluate-continuity-state.mjs --state=focused` 用于单个独立状态案例。其余状态为 `available`、`solitude` 和 `budget-exhausted`。每个独立案例使用相同初始预算。批量模式共享预算，需将剩余额度差异列为限制。

通过 `KAGUYA_CONTINUITY_EVAL_PROFILE` 指定已授权 Profile，通过 `KAGUYA_CONTINUITY_EVAL_OUTPUT` 指定私有输出目录。原始结果位于忽略目录 `.data/evaluations/continuity-20261113-*`，文件权限为 0600。后续评测入口还逐次保存 provider 的内容、usage 和终止原因，避免结构恢复覆盖早期输出，不复制请求头或凭据。

本机没有配置生产 rootless Linux broker。真实群聊交互、生产环境人工接管、稳定的自然拒绝及完整关系效果仍未验证。#328–#332 的长期活动、方法复用、训练导出和持续运行验收没有在本轮完成。
