# #211 Planner 日志驱动调优结果

2026-09-21 使用 kaguya 服务器当前 light 模型 `deepseek-v4-flash-ascend1`，在独立评测目录运行 promptfoo。旧模板通过 17/24（70.83%），最终模板通过 22/24（91.67%），提高 20.83 个百分点；两组均无服务错误。它们是同一组 12 个诊断案例各运行两次的结果，不能据此推断真实群聊总体收益。

## 发现与调整

日志中，20:50:18 的冻结规划历史已经包含 20:50:14 成功发送的评论，后续仍再次输出近义评论。本次据此要求 Planner 先检查是否已有相同交流动作，再确认新输入是否带来新的问题或可补充内容。模板同时消除“必要性门控已通过”的暗示，区分作品名、第三人称提及与直接对话，区分等待对方说完与无需参与的群友对话。

直接问题、相关兴趣、未完成请求和已解决问题同时纳入验证，避免通过一律静默来提升部分案例的分数。等待预算的提示被强化，但模型仍未稳定遵循；运行时原有的 `wait-budget-exhausted` 静默兜底保持不变。

## 保留的失败与限制

第一版全量为 22/24；强化预算指令后的定向检查为 3/4；最终版全量为 22/24。所有运行都保留，未删除失败案例或放宽断言。最终版的两次失败均为 `budget-incomplete`：`attempt=3`、`totalWaitBudget=3` 时仍输出 `wait`。因此不宣称等待预算已靠提示词解决。

三个日志案例经过匿名化，移除了记忆及人物投影，平台策略使用当前 main 的 QQ 默认策略；九个案例为人工构造。旧模板基线是当前 main 的默认模板，不是服务器旧版本完整运行链。结果只验证冻结变量到规划动作的这段流程，不验证召回、Composer 文本、消息投递或 Arousal 架构。

本次仅修改默认提示词并新增联网评测工具，没有修改线上 default/local 模板、重启服务、发布 PR 或执行远端 CI。#211 的数值唤醒职责与兴趣召回设计仍未完整实现。
