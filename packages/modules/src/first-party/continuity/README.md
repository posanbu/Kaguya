# 持续自我与活动

## 目的与非目标

将同一个 Kaguya 的自我来源、主观状态、活动和约定接入现有 Memory 与行动链。本模块不实现 #328–#332 的训练导出和长期验收。角色设定不代表现实经历。

## 消费和产生

消费策略、内部来源、活动控制、启动、有效 one-shot 到期和实际投递。产生版本化策略、状态、活动、预算、资源、内部来源、冻结输入与检查结果。普通生命周期节拍不触发模型。

## 数据流与边界

宿主提供时间、执行状态、批准工具和预算。评价先保存，活动选择再冻结。执行使用原有原生工具循环、环境租约、行动准入和回执。内部来源经唯一持久消费者进入 native Memory。人物约定引用活动，不复制执行状态。

## Settings

`autonomous` 默认关闭。`scope` 是完整来源范围。`subjectiveTtlMs` 默认三十分钟。`personaImportRevision` 标记角色导入策略。修改人设资源后应用配置，种子以新版本进入同一自我节点。

## 可靠性、幂等和失败行为

所有写入有操作身份及版本。自主调用每天最多二十四次，包括结构恢复。预算、保存点和未知结果跨重启保留。主活动与需要主行动工具的聊天在安全边界切换。结果未知的写入先核对原操作，不能盲目重试。投递成功不等于履约，对方沉默保持未知。

## 日志与可观测性

Information 保留完整来源、决策和版本引用。管理界面区分未评估、未知、过期、等待与失败。正文按来源范围读取，其他范围只可获知全局是否忙。敏感原始评测材料保存到忽略目录。

## 典型场景

Kaguya 选择公开资料，实际读取，保存笔记并回读。普通插话不取消阅读。需要聊天工具时先暂停，从保存点继续。若接受了分享约定，实际投递和原请求者反馈分别进入履约记录。人物认识更正后，依赖它的未执行计划等待重评。

启用、迁移、停用和回退说明见 [开发文档](../../../../../docs/developers/continuous/self-activity.md)。
