# QQ 表情素材维护

## 目的与非目标

`plugin.qq-expression` 仅收藏 QQ 素材并从同会话真人文字推断用法，生产默认关闭。它不处理草稿，不决定是否发言，不选择或发送表情。表情选择归属 Heavy，与正文共用一次模型调用，不依赖 Light tone 或旧 `composition` 字段。

## 消费和产生

活动订阅只消费入站消息和用法观测，产生 `collected`、`observed` 与 `learned`。Manifest 保留旧 draft、selection requested 和 prepared Kind 的声明，以便读取历史账本；它们没有活动订阅，也不会重新释放旧草稿。旧选择模板不再加载。

## 数据流与边界

素材按平台、适配器、群或私聊隔离。每条入站最多收藏一个 face、mface 或表情图片；普通照片不会自动收藏。图片仅从 HTTPS QQ CDN 下载，拒绝重定向、非图片与超过 512 KiB 的文件，副本保存在账本中。下载失败跳过收藏，后续可以重试。

每次观测冻结最多九条文字来源。Light 只用于素材语义学习，不接收图片字节，不参与最终表情选择。推断始终标记为 `context-inference`，不代表视觉识别。来源虚构、没有文字证据或模型失败时保存未知结果。已有素材间隔一分钟可重新学习；最新的低置信度推断会撤销后续请求的候选资格。

## Settings

独立实例保持 `enabled: false`。如需维护素材，可显式启用，但启用收藏不会打开回复装饰。`maxAssetsPerScope` 默认 100，最多 200；达到上限后仍可更新已有素材的语义。旧实例中的限频字段保留解析兼容，不再控制发送；发送限额配置在 Heavy 中。

## 可靠性、幂等和失败行为

收藏按会话和平台素材标识去重，观测按素材与入站消息去重。收藏队列串行执行，稳定模型请求和登记槽支持重启恢复。图片或语义任务失败不阻断普通回复。

## 日志与可观测性

`qq-expression.learn` 模板可本地覆盖；日志仅记录学习置信度，不输出素材字节。Heavy 的请求变量与引用保留素材选择依据。

## Heavy 的使用边界

Heavy 的 `qqExpressionsEnabled` 默认为 false。显式开启后只读取同会话的最新可靠语义、素材及真人证据，每轮最多冻结 24 个候选。模型只获得文字说明和 `qq-expression-N` 引用，不获得素材文件、URL 或平台素材 ID。

Heavy 根据原始对话及完整正文选择一个候选或不选。严肃、求助、冲突、不确定或证据不足时不附加，不为发送表情改写正文。没有素材或引用无效时保留原文。跨会话授权正文不加载素材，发送权限不变。

额度以持久化 assistant 为准，失败投递仍占额度；必须同时满足冷却和普通回复间隔，首次使用也需要足够回复。完成阶段串行检查额度再登记 assistant。重放使用原请求的候选与映射，不能用后来出现的素材替换原选择。素材来源和模型输出均可沿请求引用审计。正常 Unicode 文字由 Heavy 自己生成，不再经过插件剥离或追加。

## 典型场景

维护模块启用时，真人在当前群聊发送已支持的表情素材，系统收藏并学习其文字用法。后续 Heavy 已显式启用且素材可靠、语境合适、额度足够时，可以选择该素材；严肃对话或没有匹配候选时继续发送完整普通正文。
