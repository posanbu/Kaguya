# Lifecycle

## 目的与非目标

`agent.lifecycle` 是时间节拍、当前活动、睡眠唤醒和观察调度的唯一公开模块。默认实例为 `lifecycle.default`。内部 `pulse`、`activity`、`sleep`、`observation` 共用状态，不单独装配或启停。不在节拍中理解消息或直接请求模型。

## 消费和产生

消费入站、冻结情境、旧唤醒状态、观察终态及 Scheduler 到期事实。新增 `agent.lifecycle.started` 和 `agent.lifecycle.state.recorded`。保留原 `agent.attention.arousal.*`、`agent.heartbeat.*` 和 Router 契约，历史事实不改写。

## 数据流与边界

`ready` 通过受限启动能力登记恢复事实。清醒时单个持久 one-shot 推进活动。相同状态和目标延长原活动段，变化时追加一次过渡句。当前快照供控制台独立读取，模型使用按注册水位冻结的快照。节拍不进入长期记忆形成流程。

会话两分钟无实际活动后退出。全局十分钟无实际活动后入睡，未完成模型步骤阻止空闲入睡。睡眠中每五分钟复查积压，空复查继续睡。普通群消息不推迟复查，私聊、@和回复机器人立即唤醒。Light 等待仍由原调度恢复。

## Settings

- `pulse.intervalMs`：清醒节拍，默认 5000 毫秒。
- `activity.scopeIdleMs`：会话退出和关注续租共用的期限，默认 120000 毫秒。
- `sleep`：全局空闲、夜间策略和周期复查。默认开启十分钟空闲睡眠、五分钟复查，关闭夜间强制休眠。
- `observation`：保留等待预算、打断静默窗和无动作退避参数。

## 可靠性、幂等和失败行为

所有内部订阅串行提交状态。事实使用稳定操作键，Scheduler 负责持久化及恢复。重启只推进到当前时刻，不逐跳补跑。旧订阅显式复用 `heartbeat.default` 与 `attention-arousal.default` 的持久身份。存量旧实例定时任务继续消费，新调度仅归属 Lifecycle。

配置迁移同时处理模块文件和 Cordis 节点。迁移日志位于配置根 `migrations/lifecycle-v1.json`，保存旧配置和旧装配，重复执行可恢复未完成步骤。两个旧节点启停不同或存在未登记的新旧混合配置时拒绝自动合并。

## 日志与可观测性

情境页显示当前活动与最近十分钟的合并时间线，持续活动保留原开始时间。模块检查提供活动、观察历史和调度视图。普通节拍不逐条写日志或长期记忆。过渡句只用于内部情境和控制台，不发送到聊天。

## 典型场景

上午讨论低温实验，晚上没有实际活动时，当前状态已经转为发呆或睡眠。历史模型回复带时间和来源，不能代替当前活动事实。群名只取已核实来源，普通跨群话题不会自动被判为保密内容。
