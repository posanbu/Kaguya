# 事件与 Wiki 记忆

## 目的与非目标

为消息、设备观测和动作反馈提供共用的事件、实体与可追溯页面原型。实体引用已有 canonical Information ID，消息说话者与被谈论者分开保存；昵称相似不产生人物合并。默认生成器仅整理原文和显式断言，不声称完成自动人物画像、语义事实验证或跨模态身份识别。

## 消费和产生

消费 `memory.identity.person.context.completed`、`memory.knowledge.event.submitted`、证据修订请求、历史回填、脏页维护和 Wiki 刷新请求。产生事件提交、逐页回填、页面刷新、不可变页面修订及唯一处理终态。通用事件生产者必须显式给出已有来源和范围引用；动作的 requested、generated、started、completed、failed、interrupted、responded 保留为不同阶段。

## 数据流与边界

canonical 消息自动保存说话者、reply-to 和原文，昵称/群名片作为带时间的观察断言保存。被谈论者需要显式归属，不从正文猜测。其他模块通过 `memory.knowledge.mutation.requested` 可靠提交带原始证据的断言、episode、撤回与失效操作。没有页面、页面失效或刷新失败都只表示当前没有可消费证据，不能据此生成背景。

每次页面生成最多选择 8 条事件和 8 条断言，单段正文保留最多 3000 字符，并公开截断标记；完整正文仍在事件层，不能把页面当完整历史。来源范围、事件时间与入库时间分别校验。页面引用原始证据，旧页面不能反复作为新证据输入。

## Settings

模块设置为空。Profile 必须同时配置 `memory.enabled: true` 与 `memory.knowledgeEnabled: true`；缺省关闭。composition 尊重显式禁用实例。停用不会删除原始文档、事件或页面修订，原文 sparse/hybrid 与独立 Mem0 路径继续可用。

## 可靠性、幂等和失败行为

启动登记可靠回填根，按账本登记顺序每页读取最多 50 条历史身份终态和显式事件，先登记下一页再结束当前页；后续页面以父请求的 Information ID 幂等登记，事件写入按原始来源幂等。新启用或关闭后重开时会重新逐页扫描，重复来源不会产生重复事件。

页面在数据库中持久记录 dirty 状态，刷新冻结页面版本、dirtyVersion 与双时间截止点。并发更新通过 CAS 检查，冲突重新安排最新脏页；revision 的 operationId 使数据库提交后崩溃重试复用同一修订。错误交给 Reliable Runner 有界重试与耗尽诊断，不调用外部 provider。

## 日志与可观测性

模块检查页展示只读 Wiki 修订、原始 Information 引用、证据截止点、截断标记及任务结果。这里展示的是历史修订；业务读取通过 `readWikiPage` 检查当前 dirty 状态，失效页面不能作为当前认识。普通日志不输出正文和媒体链接。

## 典型场景

同一账号改昵称后，继续关联同一人物实体，旧名称观察和新名称观察都可追溯。设备的失败回执可作为独立事件录入，在页面上保留失败阶段，不把此前生成的指令视为执行成功。多人偏好纠正用不同陈述者的断言表达，显式修订只影响指定断言，原文仍可检索。
